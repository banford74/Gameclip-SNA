# P/R 码表演化（RL / bootstrapp 路线）

> 目标：原始 P/R 码表来自单一品类（手游买量战斗向）。8 游戏 × 多形式语料会不断暴露缺口——新情节（音乐/舞蹈、攻略、日常、开箱、联动）与映射失真（P114 误报等）。码表必须**边分析边扩**，而不是一次性定稿。

## 一、循环结构（reward / policy / iteration）

| 环节 | 实现 | 说明 |
|---|---|---|
| **Harvest** | `python -m pipeline.codebook_loop harvest` | 统计所有已分析结果：P/R 频次、P↔R 共现、无 P 码覆盖样本、低置信样本 |
| **Propose** | `propose` | 按形式缺口提出新码候选（P116–P120 / R914–R917）+ 映射修正建议 |
| **Review** | 人工/LLM 裁决 | 候选码逐条确认（名称/定义/R 映射/证据） |
| **Activate** | `activate --codes P116,R914` | 写入 `configs/pr_codebook_ext.json`，`pr_codebook` 自动加载（开启后进入打标 prompt 与校验） |
| **Re-run** | 重跑分析 → 回到 Harvest | 奖励信号 = 与人工 gold 的 P/R 命中 F1、映射支撑度、置信校准 |

**Reward 定义**（用于决策"是否保留新码/新映射"）：
```
score = 0.5 * P_code_F1 + 0.3 * R_hit_agreement + 0.2 * confidence_calibration
```
其中 confidence_calibration = 1 - |预测置信 - 实际正确率|（分档统计）。

## 二、当前 harvest 结果（2026-11-23，30 条既有分析）

- P 码频次：P114(18) > P101(9) > P115(4) > P105(3) ≈ P104(3) > P112(2) > P113/P106(1)
- **无 P 码覆盖：6 条**（形式缺口：攻略教学 1、未标注 5）
- 观察：P114 占 60%——与"变装/外观"在游戏内容中高频一致，但也提示它可能是"垃圾桶码"（需要拆分：换装 vs 武器形态切换 vs 外观展示）。

## 四、映射修正（从共现统计自动生成）

`harvest.json` 的 `mapping_support` 给出每个 P 码实际共现的 R 码占比。规则：
- 共现占比 ≥0.6 且样本 ≥10 → 建议加入该 P 的 `r_map`；
- 映射 R 码共现 <0.2 → 建议移除或降权；
- P 码拆分：若某 P 的共现分成两个簇（如 P114 的"换装簇"R302/R352 与"武器形态簇"R354）→ 拆成两个码。

## 五、运行方式

```bash
# 1) 统计残差（每次批量分析后跑）
python -m pipeline.codebook_loop harvest
# 2) 生成候选
python -m pipeline.codebook_loop propose
# 3) 人工/LLM 裁决后启用
python -m pipeline.codebook_loop activate --codes P116,P117,R914
# 4) 重跑分析，回到 1)
```

产物：`data/codebook_loop/harvest.json`、`proposals.json`；扩展配置 `configs/pr_codebook_ext.json`。

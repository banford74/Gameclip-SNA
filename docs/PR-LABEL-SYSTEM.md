# 标签体系判断：P/R 为主、十级为参照（多游戏泛化 + 防过拟合）

> 结论：**P/R 双层体系（15 P 码情节层 + 91 R 码视觉特征）作为本项目主标签**；十级机械标签（和平精英 CG36/CG37 版本体系）**已弃用**（对跨游戏任务无帮助），但其**知识蒸馏 + 三路投票 + 置信分层**的工程方法全部移植到 P/R 上。
> 依据：2026-11-22 实测（v3 地铁逃生实录，114.7s，P111/P109/P112，置信 high）+ 十平台历史跑批（P/R 在两条素材上已有可比较的命中/误报记录）。

---

## 一、为什么 P/R 主、十级辅

| 维度 | P/R（15+91） | 十级机械（CG36/CG37） |
|---|---|---|
| 泛化 | 跨游戏通用（R6 组纯实录/BGM/画幅/剪辑等是品类无关的创意特征；P 码是叙事原型） | 版本/玩法强绑定（地铁逃生、古墓迷途、超体…），换游戏即失效 |
| 与任务对齐 | P 码 = 叙事骨架 → 直接喂 Task A（内容 stance）；R 码 = 画面证据 → 可审计 | 十级偏「素材管理/投放归类」，与观众情绪传递的机制距离远 |
| 样本效率 | 91 项均为有/无 + 少数枚举，标注便宜，2000 条可控 | 十级需版本词表 + 层级父子关系，标注/维护成本高 |
| 已有实证 | 十平台跑批已用 P/R：v1 P101+P114、v2 误报 P104/P114 的残差模式清晰 | 迁移包内实验（86.9% 三路投票）证明了方法有效，但只在和平精英 CG37 上验证 |
| 过拟合风险 | 低（体系静态、跨游戏） | 高（版本词表会把「和平精英玩法」学成通用标签） |

**十级体系保留的用途**：多游戏时的「玩法/版本」辅助特征（可选打标维度），以及 `v2_rl_library.xlsx` 到位后的知识蒸馏演示。

## 二、从十级体系移植的五件方法（已落到 P/R 代码）

| 十级做法 | P/R 移植 | 落地位置 |
|---|---|---|
| 版本专属受控词表 | 词表静态（15 P + 91 R），**先验按游戏/形态分组学** | `pr_codebook.py` + `knowledge.py`（分组先验可扩展） |
| 少样本标杆 | gold 集每类取代表样本进 prompt | `pr_tagger.py` 预留 fewshot 槽位（接 gold 后启用） |
| 关键词先验 | 开场 R 码（R101/R102/R103/R104）分布先验 | 同上 |
| 共现/表里映射 | **P↔R 映射表**（15 条 P 各带 2–3 个映射 R）→ 规则层 B 路 | `pr_codebook.rule_p_codes()`（≥2 映射 R 命中才出 P 候选） |
| 确定性链路 | R601→R403=0%、R801=时长、画幅枚举→R805、P→R 支撑校验 | `validate_pr()` 一致性检查 + `p_missing_support` 诊断 |
| 三路投票 + 置信分层 | A=VLM、B=规则层；**任意两路一致→high，单路→medium/low**（C=语义 bge 待装） | `pr_tagger.tag()`：实测 v3 = high（A+B 一致） |
| 主动纠偏闭环 | clips.csv 的 `human_correction` 回填 → gold → 软标签/微调 | `cloud.py` + `piteline/soft_labels.py` |

> 两路投票无意义、偶数票平票缺陷、语义不能当纠偏器——这三个教训直接沿用：**P 码投票保持奇数路（A+B+C），文件名/元数据只做兜底不做票**。

## 三、多游戏 / 多形态：防过拟合设计

### 1. 配比方案（`pipeline/configs/balance_plan.json`）

- **游戏**：和平精英 20%、原神 15%、三角洲 15%、王者 15%、蛋仔 10%、光遇 10%、其他 15%
- **形态**：实机 25%、短剧 15%、攻略 15%、音乐舞蹈 10%、混剪 10%、真人 10%、图文 8%、其他 7%
- **结果分层**（评论 valence）：正 40 / 负 30 / 中 20 / 混合 10
- **约束**：单游戏 ≤25%、单形态 ≤30%、每 P 码 ≥30 条、每 R 组 ≥50 条

### 2. 切分与 OOD

- 分组切分：**按创作者 + 游戏 + 形态分组**（同一创作者不跨 train/test）
- **留出泛化测试**：整个「光遇」+「音乐/舞蹈」形态不进训练集，专门测未见域
- v2 复盘教训：P104/P114 在测评/纯展示素材上误报高发 → 负样本按 1:2 补足（这类素材也须进测试集）

### 3. 训练侧防过拟合

- 软标签（多 rater + 置信门控）+ 参数高效（SALFT/LoRA 只动尾部情感层）
- 早停看分组 val；CH-SIMS 防退化门（掉幅 >2pt 报警）
- 标签置换检验（`falsify.py`）：同品类内打乱目标，增益必须塌缩到 chance

## 四、GitHub 云端链路（2000 条 → 链接 → 人工真值）

`pipeline/ua_agent/cloud.py`（REST API，无需 gh CLI）：

```
每条 clip：
  agent 打标 → annotation.json（P/R + ua10 + 逐帧）
  → release 上传（关键帧/可选视频）→ 公开直链
  → 追加 data/clips.csv：clip_id / 链接 / AI 标签 / pr_conf / human_correction / review_status
人工：打开 clips.csv 或 release 预览 → 填 human_correction（修正 P/R、补情感）→ review_status=corrected
回写：human_correction → gold → soft_labels → train_taskA / taskB
```

**规模注意**：
- GitHub 单文件 2GB；release 资产数建议每批 ≤100–200 个文件 → **只传关键帧**（~100KB/张）做预览，视频留本地/对象存储
- 2000 条 = 2000 张关键帧 ≈ 200MB，分 10–20 批 release，完全可行
- 若要把视频也托管：建议 R2/COS 预签名 URL，csv 里换成对象存储直链
